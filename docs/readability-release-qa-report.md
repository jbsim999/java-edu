## 새 패키지의 정적 대조

빌드 ASAR, ZIP 추출본, NSIS 내부 payload의 **197개 소스+24개 생성물**을 검증 소스와 비교했다. 포함 도구604개의 manifest·파일 목록·크기·해시를 검사했으며 bundle ID는 `548c060050b821dbcb99fd90e3f9e992e47e6ab3899d12551c9d7fb965581760`다. ASAR SHA256은 `b78441c83a849aa728145cecb8d993b8e2cf8afbfdc7de303ad6de205720b00f`다.

ZIP은 전체678파일, NSIS payload는 전체679파일을 빌드본과 대조했다. 초기 집합 비교에서는 ZIP의 `resources/elevate.exe` 부재 때문에 실패했다. electron-builder26.15.3의 NSIS 단계가 해당 vendor helper를 나중에 복사하는 타깃 차이를 원본 코드와 실제 파일로 확인했다. ZIP에서 이 한 경로만 명시적으로 제외하고, 빌드본·NSIS payload·공식 NSIS3.0.4.1 원본의 helper 해시 `9b1fbf0c11c520ae714af8aa9af12cfd48503eedecd7398d8992ee94d1b4dc37`가 일치함을 확인했다. 다른 누락·추가 파일은 허용하지 않았다. 포함 도구와 제품 패키징 설정은 변경하지 않았다.

추출 입력 EXE·ZIP의 해시를 추출 전후와 결과 대조에 연결했다. 7-Zip의 NSIS EXE 내부 ZIP 읽기는 후미 데이터 경고와 exit0을 반환하며, 이는 설치 실행 성공을 뜻하지 않는다. 증거는 `work/readable-desktop-qa/extract-*.json`, `package-*.json`, 추출 로그다.

## 검증의 경계

사용자가 Downloads의 v0.3.0 앱을 사용 중이고 AppData 학습 기록이 존재해 absence preflight를 통과하지 않았다. 이 앱을 종료하거나 데이터를 옮기거나 삭제하지 않았다. **새 v0.3.1의 실제 설치·앱 실행 검사는 BLOCKED·미실행**이며 정적 payload 비교와 브라우저 검증으로 구분한다. v0.3.0의 실제 설치/제거·앱10/10 결과를 신버전의 실제 실행 결과로 사용하지 않는다.

브라우저 API는 모의 응답으로 격리했으며 실제 Java 제출 성공이 아니다. 200%는 문서 글자 확대, 모바일·터치는 브라우저 에뮬레이션이다. 실기기·스크린리더·OS IME/클립보드·실제 학습 효과·선택 Redis/Kafka 연동은 미검증이다. 넓어진 CSRF/JWT 도식의 마지막 행 빈 공간은 비차단 시각 개선 사항으로 남겼다.

웹 배포 체크아웃에서는 소스 동기화 완료 전의 선행 빌드가 v0.3.0/35 PASS 로그를 반환하는 작업 순서 오류를 확인했다. 중간 결과를 폐기하고 전체274파일의 Git blob 일치를 확인한 뒤 같은 v0.3.1 소스로 다시 빌드·Worker 검사·Node40 PASS/1 SKIP를 확인했다. 배포에는 이 최종 소스와 산출물만 사용한다.
