# Java 공통 코어: 교재와 실습 계약

기준일: 2026-10-12. 대상은 다른 언어로 프로그래밍 경험이 있는 Java 전환 학습자와 현직 Java 개발자다. 이 문서는 현재 작성한 12개 시작 수업의 범위와 편집·평가 기준을 설명한다. 완전한 Java·Spring 실무 교육과정의 완성 선언이 아니다. 전체 16단계 교육 로드맵과 제품 기획은 별도 문서를 따른다.

## 학습 흐름

각 수업은 이론 → 예시 → 문제풀이 → 실무 심화 → 웹 IDE 직접 코딩의 다섯 단계로 구성한다. 실행 가능한 IDE는 첫 공개 MVP의 필수 기능이다. 수업 데이터와 채점 데이터가 준비되었다는 사실은 실행 서버·브라우저·격리 환경의 통합 검증 완료를 뜻하지 않는다.

전환 학습자는 값 전달과 객체 모델에서 시작하여 OOP·타입 안전성·실패 처리를 공통 코어로 학습한다. 현직자는 코드 해석·수정·설계 설명의 진단으로 통과한 단원을 건너뛰고 부족한 코어와 버전 심화를 연결한다. 경력·객관식 점수 하나만으로 단원을 면제하지 않는다.

권장 선수 관계는 다음과 같다.

- Java 객체·타입 모델 → 책임·불변식 → 다형성·계약·의존 관계.
- 객체 모델 → 컬렉션의 동등성·변경 계약 → 제네릭 API 경계.
- 객체·컬렉션 → 예외·자원·Stream → 테스트 설계.
- 가변 상태·실패 처리·테스트 → JMM·동시성.
- 공통 코어 → Java 11 API → Java 17 결과 모델 → Java 21 패턴·가상 스레드.

테스트 설계는 데이터 목록의 표시 위치와 관계없이 동시성 심화 전에 학습하거나 진단으로 통과하는 것을 권장한다. 학습 시간은 난이도와 경험에 따른 참고치이며 고정 수료 기간이 아니다.

예제는 독립적인 `Main.java`이며 외부 라이브러리 의존성이 없다. 웹 실습은 전체 `class Solution`을 편집한다. 메서드 본문형에도 클래스·메서드 시그니처를 제공하지만 이 단계의 에디터는 수정 범위를 강제 잠그지 않는다. 클래스 골격형은 외부 호출 계약을 문제 설명에 명시하며 내부 필드와 협력 구조는 학습자가 설계한다.

제네릭 복사 과제는 source와 target이 저장소를 공유하는 뷰·래퍼 관계가 없고, target이 source의 모든 요소를 수용할 수 있다는 전제에서 수행한다. 서로 다른 객체라는 조건만으로 구조 변경의 독립성이 보장되지는 않는다. [Java SE 8 List.subList 계약](https://docs.oracle.com/javase/8/docs/api/java/util/List.html#subList-int-int-)에서 원본과 뷰의 관계를 확인한다.

## 평가를 구분하는 원칙

1. **컴파일·실행 성공**: 코드가 대상 버전으로 컴파일되고 표시된 JVM에서 실행되었다.
2. **행동 검증 통과**: 명시한 자동 테스트에서 기대 행동이 확인되었다.
3. **설계 검토**: 책임·캡슐화·의존 관계·타입 사용·동시성 근거를 설명 루브릭으로 검토한다.

자동 테스트 통과만으로 객체 설계나 동시성 숙련을 인증하지 않는다. 예를 들어 concurrency 과제에서 단순히 workers × iterations를 반환하면 일부 행동 검사를 통과할 수 있다. 실제 작업 제출·원자 연산·완료 대기·실행기 종료는 설계 검토 대상임을 공개한다. 제네릭의 raw type 우회, Stream을 사용하라는 학습 요구도 동작 테스트만으로 완전히 판단할 수 없다.

실행 결과와 설계 검토 대기를 화면에서 구분해야 한다. 설명란에 글자를 입력했다는 사실만으로 설계 평가를 통과 처리하지 않는다. 실패 피드백은 컴파일 오류, 실행 오류, 기대 행동 불일치, 환경·지원 버전 문제를 구분한다. 학습자는 코드를 보존하고 재시도할 수 있어야 한다.

객관식은 수업당 두 문항이며 정답과 해설을 함께 제공한다. 코드 실습은 공개 샘플 검사와 추가 행동 검사로 구성한다. 검사 대상은 명시된 입력 계약이며, 문서에 없는 조건으로 학습자를 실패시키지 않는다. 공개 저장소의 기준 답안과 검사 파일을 비밀 평가 장치라고 표현하지 않는다.

## 공식 근거와 버전 편집

- 언어 의미는 해당 Java SE의 JLS, API는 API Specification의 계약·Since, 실행 모델은 공식 가이드를 우선한다.
- sources에는 title, url, edition, checkedAt을 기록한다. checkedAt은 자료 확인일이며 기능 출시일이 아니다.
- minVersion은 8·11·17·21 중 이 수업 예제와 실습을 지원하는 최소 대상이다.
- featureSince는 대표 기능의 최초 도입 버전이다. 서로 다른 도입 시점의 공통 개념을 묶은 경우 null로 두고 본문에 개별 기능의 버전을 적는다.
- 제네릭은 5, 지역 변수 var는 10, 람다 매개변수 var는 11, switch 표현식은 14, text block은 15, record와 instanceof 패턴은 16, sealed는 17, record pattern·pattern switch는 21에서 정식 도입되었다.
- Java 8 예제에 List.of·Stream.toList·Optional.isEmpty를 섞지 않는다. Java 17에 preview pattern switch를 섞지 않는다.
- 모든 현재 수업은 preview: false다. record의 깊은 불변성, volatile의 복합 연산 원자성, 가상 스레드의 자동 CPU 가속을 주장하지 않는다.
- 설계 원칙·LSP·SOLID의 적용 판단은 교육적 해석이다. Java 명세가 특정 설계 패턴을 의무화한다고 설명하지 않는다.

원문을 그대로 옮기는 방식보다 한국어 설명·자체 예제·반례를 작성하고 근거 문서를 연결한다. 예제의 출력이 바뀌면 교재 코드, 독립 Main.java, expected-output.json을 함께 수정한다. 과제 계약이 바뀌면 공개 metadata, trusted 검사, 기준 답안을 함께 갱신한다.

## 실무 연결 범위

현재 12개 실행 과제는 순수 Java이다. 수동 의존성 주입을 Spring 실행으로, 직접 AssertionError를 던지는 검사를 JUnit 실행으로 표시하지 않는다. Spring·Lombok·MyBatis·JPA·OAuth 2.0·OIDC·Redis·Kafka 등은 전체 로드맵에서 의존성·DB·HTTP 통합 실행 능력이 준비된 단원으로 확장한다.

jobTags는 교과와 공고 근거를 연결하기 위한 분류다. 태그가 있다는 사실만으로 해당 수업 내용을 특정 기업이 요구했거나 출제했다는 뜻은 아니다. 실제 공고 관찰은 별도 job-evidence 자료의 URL·확인일·요구/우대·접근 한계를 따른다. 교육상 필요한 보완 기술과 공고 본문에서 실제 확인한 기술을 구분한다.

작성 시 데이터 연결·예제 동일성 검사와 설치된 JDK의 컴파일·출력 비교를 수행한다. 실제 실행한 환경·대상·검사 수는 통합 검증 기록을 따른다. JDK 21에서 --release 8로 컴파일한 결과와 실제 JDK 8에서 실행한 결과는 다른 검증으로 기록한다. 브라우저 IDE 통합·실행 격리·접근성 검수는 별도 담당 결과를 확인한 뒤 공개 준비 여부를 판정한다.

- Java 11·17·21 예제와 답안은 이 로컬 JDK 8 검사에서 실행하지 않았다. 이후 통합 담당자의 실행 환경 검증과 구분한다.
