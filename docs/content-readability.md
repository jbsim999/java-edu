# 코드로 이해하는 교재 작성 기준

다른 언어 경험자와 현직 Java 개발자가 개념을 실제 코드에 연결하도록 작성한다. 공식 문서는 정확성을 확인하는 기준이다. 명세의 문장 순서를 교재의 설명 순서로 사용하지 않는다.

## 이론 안의 설명 순서

1. 구체적인 상황과 질문: 어떤 입력·호출에서 예상과 다른 결과가 생기는가?
2. 용어와 뜻: 이 상황을 설명하는 용어를 실제 변수·객체·메서드와 연결한다.
3. 핵심 코드: 기존 예제에서 연속된 부분을 그대로 발췌한다. 전체 코드와 구분하며 예제 탭에서 원문을 제공한다.
4. 순서대로 읽기: 호출 전 값, 실행되는 분기, 바뀐 값, 실패 후 남는 상태를 설명한다.
5. 결과 예측과 해설: 독자가 먼저 생각한 뒤 답을 펼친다. 이 활동은 퀴즈·실제 제출 성취로 기록하지 않는다.
6. 적용할 판단: 실무에서 무엇을 확인하거나 선택해야 하는지 한 문장으로 정리한다.

이 흐름 뒤에 기존 상세 이론과 검수한 도식을 제공한다. 코드 해설이 다루지 않은 추가 개념은 기본 본문에 남긴다. 학습 목표·수업 메타데이터는 수업 정보에서 펼쳐 확인하며, 공식 출처와 실무 공고도 별도 펼침 영역으로 제공한다. 수업의 이론 → 예제 → 문제 → 실무 → 코드 실습 구조는 유지한다.

## 본문을 위한 화면 공간

수업 화면은 목차와 본문을 중심으로 구성한다. 반복되는 큰 소개·통계·워크스페이스 표제는 줄이고 전체 진도와 이어서 학습은 보존한다. 참고자료가 본문 옆의 상주 열을 점유하지 않도록 한다. 좁은 화면과 글자 확대에서는 바깥·안쪽 여백의 상한을 낮추며 글자 크기를 줄이거나 페이지 넘침을 숨기지 않는다.

## 쉬운 설명에서도 지킬 정확성

“잔액이 바뀌어도 음수가 되면 안 된다”처럼 구체적인 상황을 설명한 뒤 불변식이라는 이름을 붙인다. 용어만 다른 추상 용어로 바꾸거나 비유만으로 설명을 마치지 않는다. 정상 결과와 실패 결과를 함께 설명한다.

언어 명세의 보장, 프레임워크의 기본 설정, 이 예제가 선택한 정책을 구분한다. 참조값 복사와 객체 복사, 가시성과 연산 원자성, flush와 commit, OAuth2와 OIDC, 검증용 fixture와 전체 프로토콜 구현을 같은 뜻으로 설명하지 않는다. 조건과 반례를 생략해 잘못된 단정으로 만들지 않는다.

## 검수 범위

34개 수업의 가이드 구조·원문 발췌·실행 계약 보존을 검사한다. 독립 내용·코드 검토와 실제 브라우저 화면·접근성·진도 회귀 검사를 수행한다. 실제 설치 패키지는 별도로 확인한다. 자동 검사와 검토 통과는 실제 학습자의 이해도 향상을 측정한 결과가 아니다. 검수 결과는 [교재 가독성 QA](readability-qa-report.md)에 기록한다.
